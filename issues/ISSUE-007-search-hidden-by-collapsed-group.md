# ISSUE-007 搜索结果被折叠分组隐藏

- 状态：fixed
- 发现日期：2026-10-18
- 相关文件：`src/client.js`

## 现象

「模型暴露」配置面板中：折叠某个分组后，在搜索框输入该分组内模型的关键字，列表显示「没有匹配的模型」或缺少该组的匹配项——明明存在的模型搜不到。

复现步骤：
1. 打开 OC-bridge 面板，点某分组的 ▾ 折叠该组；
2. 在搜索框输入该组内任一模型名（或其片段）；
3. 预期：搜索结果包含该模型；实际：该组匹配项不可见。

## 原因

渲染分组行时的折叠判定 `isCollapsed = collapsed.has(g.key)` 只看用户的折叠记忆，不考虑当前搜索过滤后的可见性。搜索把候选集缩小到 `shown`，但折叠状态仍把含匹配项的整组内容跳过渲染，匹配项被折叠状态吞掉。

## 修复方案

- `src/client.js`：折叠判定改为 `isCollapsed = q === "" && collapsed.has(g.key)`——搜索词非空时忽略折叠状态（所有命中组展开显示），用户的折叠记忆保留，清空搜索后原折叠状态恢复。
- 同批（P1 交互修正）一并处理的相邻问题：
  - dirty 未保存状态：`saved` 基线集合 + 对称差计数，「未保存更改 ×n」提示，保存按钮仅 dirty 可点；
  - 「重新加载」丢弃未保存勾选前弹 `window.confirm` 确认；
  - 计数语义：筛选时显示「已选 n · 显示 m / 共 total」，不再把全量 total 冒充筛选总数；
  - 死文案 `serviceDown` 接入：fetch 网络失败 / 404（host connection 路由未注册）时显示该提示；
  - 状态反馈：保存成功提示 2.5s 自动淡出，状态 pill 限宽换行（长错误不再撑坏底部布局）。
- 验证：`npm test` 206/206（含 build-client 重建 lib/client.js）；面板行为由实机点击复现验证（client 半区页面刷新生效）。
